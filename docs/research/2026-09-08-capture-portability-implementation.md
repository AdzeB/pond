# Capture and portability implementation evidence

This records the implemented slice of the Eagle parity work on September 8, 2026. The shared working tree contains other agents' changes. Nothing was committed by this task.

## Implemented

- Export Files copies every original of every selected Save, including multi-file Saves. Folder membership becomes a directory hierarchy, with copies for multiple memberships. Existing names, including case collisions, receive suffixes; exclusive writes avoid overwriting files. A manifest records metadata and file mappings. Agent export uses the same engine. Conversion exports use its collision-safe write helpers.
- Duplicate merge preserves the chosen survivor's scalar fields; unions tags, folder memberships, image comments and video notes; copies extra original files before trashing duplicates. Original duplicate files remain recoverable in Trash. Agent merge stores a receipt and restores the survivor metadata and duplicate Saves on Undo. Undo refuses if the merged metadata changed afterward. Merge and Undo serialize with each other.
- Watched folders reconcile recursively on startup and periodically, wait for stable size/time, hash and snapshot a source before importing, retry failed outcomes, persist successful source checksums, and identify repeated ingestion by path/content. Move mode removes only a successfully imported unchanged source. Stop waits for the current import; library changes drain the originating importer first.
- Folder import creates the actual directory tree, preserves empty folders, applies selected tags and folder memberships, and reports partial failures internally.
- Backup stages a copy, checks every original reference and checksum, compares source inventories before/after copying and the destination inventory, then publishes a checksum manifest. A source edit during copying aborts publication. Failure never recursively deletes a user's chosen destination.
- Restore verifies the backup, makes a separate copy, retains the source snapshot, and adopts the restored copy. Backup, Restore, Move and Open are serialized. Move uses verified copying. Tags and the root agent's portable metadata backfill are flushed before copying. Open directs checksum snapshots to Restore instead of editing them in place. Settings has Restore and package import controls.
- `.pondpack` is a directory package using the shared export manifest. Selected Saves retain every file, exact original file paths and kinds, nested archived assets, zero-byte attachments, source identity and raw source data, notes/tags, ratings/annotations, dates, dimensions, media type, viewing transforms, captions/OCR/transcripts and model names. Import validates all files and folder references before mutation, checks copied hashes again, assigns new Save IDs, and skips existing source identities. The original package stays intact. Export is available in the Save menu; Import is in Storage settings.
- Transfer admission drains package operations, folder/Eagle imports, exports and duplicate merges before changing library pointers. Nested admitted exports finish while the gate drains. Quit integration must also await the location-operation queue.
- Verify Integrity now checks actual original references/checksums in addition to the existing live index/orphan comparison.
- Copy to Library exports a temporary package and transfers directly into another initialized library, retaining its existing Saves and organization. Merge Library reads an existing library and imports its live Saves, folders, Smart Folder/Group/Saved View tree, query inheritance, view layout/sort/question, tag definitions and group/member ordering. Folder predicates and parent IDs are remapped. Identical views and source identities make retries idempotent; existing tag/group metadata wins name collisions. Invalid query references or cycles reject before importing. Original source libraries remain intact.
- Recent libraries are recorded in application storage; Storage settings offers a picker and retains unavailable locations as disabled entries.
- Library changes stop watched-folder work, drain admitted transfers and background reconciler workers, then close mutation admission and drain queued mutations. Backups/failures resume the original reconciler pause preference. Development switches close the old database, invalidate root/preferences, clear Undo history, then reopen admission before new-root reconciliation. Production transitions stay closed until relaunch. This shares the executor admission mechanism with manual file imports and pipeline persistence.
- File imports initially persist an ingesting state. A retry with the same source identity resumes an incomplete Save rather than skipping an empty row left by interruption; successful results require the expected original files and sizes. User-named capture title markers survive package and library transfer.

- Automatic tags are stored with the library's preferences. Child folders inherit every ancestor's tags. Assignment and subtree moves add tags together with folder changes in one journaled batch; Undo restores the former tags and memberships/parent. Removing a folder membership retains the Save's tags. The folder context menu includes searchable automatic-tag configuration, optional application to existing descendants, multiline folder creation and searchable multi-folder moving. Invalid descendants/cycles are rejected; selected children stay inside a selected parent during a batch move.
- Manual imports create the canonical tag registry entries and Save row through one executor batch, fixing Saves whose tags were invisible in the Tags sidebar. Package imports also preserve or create canonical tag definitions, including legacy packages without registry metadata. Folder import validates and orders its parent tree before writing; repeated active package imports reuse the destination folder path.
- Export Files, package export/import, Copy to Library and Merge Library persist transfer jobs in application storage. Downloads and Storage display phase progress with Cancel and Retry. Cancellation stops at a file boundary. Completed export outputs have durable checkpoints; retry verifies their hashes before reusing them and preserves user-modified outputs by choosing a new name. Packages can restart staging; import retries skip completed source identities. Unfinished jobs become Interrupted after restarting Pond and await explicit retry with the original library open.

## Eagle migration

The official [library API example](https://api.eagle.cool/library/info) describes `smartFolders`, `tagsGroups`, tag-intersection conditions and relative `createTime` rules. Pond now imports tag groups, preserves appended member ordering, imports supported Smart Folders idempotently, and retains relative dates as rolling queries. Unrecognized Smart Folder structures, unsupported conditions and Quick Access are reported through `droppedFields`; the Storage result now displays those losses.

The official [item API example](https://api.eagle.cool/item/info) stores palettes as RGB objects. The importer now converts these to hex colors while retaining legacy string palettes, carries Eagle's stored item timestamp and optional creation timestamp, and recognizes folder `iconColor`. Malformed item JSON fails that item instead of aborting the entire import. Folder trees, ratings, annotations, custom thumbnails and video notes were already supported.

The installed Eagle 4.0.0 Build 23 application (buildVersion 20260401) was also inspected as a primary source for serialized rule semantics. Its Smart Folder model and rule handlers confirm that empty conditions plus children represent Groups, parent conditions are inherited, condition blocks combine with AND, and each block's FALSE flag negates its AND/OR result. Tag/folder intersection means all selected values, union means any, equality means exact set, and identity means none. File size and duration units are converted; creation-time ranges preserve Eagle's day endpoint convention. Recursive Groups now import with their inherited conditions. Regex, color tolerance, EXIF fields, modified/birth-date rules, and other unmapped operators are reported and skipped along with dependent children rather than broadening membership.

## Remaining boundaries

- Snapshot consistency combines worker/transfer/mutation draining with source/copy verification. External writers or synchronization tools can still cause a retryable snapshot failure. This is not certification of concurrent cloud-library writers.
- A destination transfer uses an exclusive process/host lock and rejects organization changes observed during copying. It recovers same-host dead-process locks. Other application processes or cloud clients do not participate in this protocol; no universal distributed lock is claimed.
- Selected `.pondpack` exports carry Saves, their tag definitions, folder ancestry, automatic-tag rules, and folder presentation (layout, sorting, shuffle seed, icon, and manual order). Imported manual order maps source Save IDs to copied or existing destination IDs; unselected IDs are omitted. Whole-library merges additionally carry saved views and tag-group definitions. Existing destination folder presentation wins collisions, manual order appends copied Saves, and automatic tags are combined. Connected accounts and unrelated preferences are excluded. Whole-library backups retain all root bundles.
- Transfers retry at file or Save boundaries, not at a byte offset. A metadata commit failure retains copied originals for recovery. Multi-Save import is not fully transactional. General capture drafts remain separate work.
- Unsupported Eagle rules are explicitly reported migration losses. Native UI behavior and real-world performance require root's packaged smoke and manual acceptance checks; test coverage here does not imply measured Eagle speed parity.
