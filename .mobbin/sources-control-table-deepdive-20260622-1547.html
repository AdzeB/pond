Pond · Sources redesign — Idea 1 deep dive

Control table

One table, every source a row. The detail view isn't a separate page — a row expands in place into a monitoring panel: stats, a run-duration sparkline, the full run timeline, error detail, and source-specific maintenance. Below: the anatomy, every status state, and density options.

01 Primary view

Sorted by attention: running first, then errors and sign-in, then healthy, then not-connected. A summary bar gives the one-glance state. Row actions reveal on hover so the resting table stays calm.

05 Behaviour & build notes
Sorting by attention. Running → error/sign-in → synced → not-connected. Within a bucket, most-recent activity first.
Live, no refresh. Rows already subscribe to onSyncStatus; the expanded panel re-pulls sync.history when a run finishes.
One expand at a time. Opening a row collapses the previous — accordion behaviour keeps the page short.
Reuses existing data. Stats and timeline come straight from the pipelineEvents rows we already write per run.
Calm at rest. Row actions fade in on hover/expand; the resting table is just status + counts.
Bulk + maintenance. “Sync all” in the header; per-source maintenance (tweet screenshots) moves into the panel footer.

Static mockup for direction-setting. Builds on Idea 1 from the previous board. Primary references: Sana AI (status-rich connected table) and Replit (sectioned rows with inline status + action).
